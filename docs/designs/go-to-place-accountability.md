# CEO Plan: BallotWatch as the Go-To Place for Representative Vote Accountability

## User's stated vision

> "I want ballotwatch to be the go to place for information on what a representative has voted on"

## Premise (chosen in Step 0A)

**Job-to-be-done:** Accountability. When a voter or journalist lands on BallotWatch, they are asking "is my rep actually representing me?" — not just "what did they vote on?" This framing plays directly to BallotWatch's existing differentiated assets (AI voting-pattern analysis, campaign-finance industry overlay, editorial design) and creates a unique wedge vs GovTrack (archival truth, no accountability framing) and Congress.gov (official source, no narrative).

## Strategic context

**ProPublica shut down their Congress tracker in 2023-2024.** The gold-standard public-facing source for congressional voting data no longer exists. Journalists, activists, and developers actively need a replacement. This is a real, measurable void that "go-to place for votes" can fill — if BallotWatch executes on the SEO, citation, and retention flywheels.

**Current product asset inventory (keep all, per focus audit):**
- Editorial/broadsheet design system (DESIGN.md)
- Congress.gov + Senate XML + FEC + Census ETL via GitHub Actions
- 538-style voting dashboard on politician profiles
- AI voting-pattern analysis with district-lean mismatch (`votingPatterns.js`)
- Campaign-finance industry × votes correlation (`donations.js::getMoneyVotesCorrelation`, `industryMap.js`)
- B2B API at `/api/v1/*` with Developer Portal
- Adjacent features (ShutdownTracker, AI Congress sim, district map, blog) retained as top-of-funnel

## Vision

### 10x Check

Three flywheels turning simultaneously:

1. **SEO flywheel** — every vote, every rep × every issue has a dedicated page ranking #1 for long-tail accountability queries. Millions of low-competition queries ("did [rep] vote [issue]"). This is how voters find you.
2. **Journalist citation flywheel** — reporters writing "Rep X voted against Y despite $Z from industry" cite BallotWatch. Every citation = backlink + authority. Makes BallotWatch the "default source" — which is literally the definition of go-to.
3. **Voter retention flywheel** — email alerts "every vote Rep X takes." Stickiest channel in civic tech. Users compound over years.

### Platonic Ideal

7:42am, Tuesday. Voter hears: "Senate voted on SNAP reauthorization last night." → Googles "Rubio SNAP vote" → First result: `ballotwatch.com/vote/2026-04-18/snap-reauth-rubio` → 500ms load → sees Rubio's Nay, plain-English bill summary, Rubio's historical pattern on food votes (Nay on 7 of 10), agribusiness donor context ($2.1M this cycle), district-lean mismatch, shareable card pre-composed with all of it. User tweets card. Each click brings in another voter.

30 seconds from question to understanding, with the accountability context already there.

## Accepted Scope (added to this plan)

1. **SSR/SSG migration for per-vote pages** — `/vote/:congress/:chamber/:rollcall-slug` + `/rep/:slug/vote/:rollcall-slug` + `/rep/:slug/issue/:policyarea`. Candidates: Next.js App Router, Astro with React islands, or vite-plugin-ssr. Decision to lock in during /plan-eng-review.
2. **OG vote card edge function** — `@vercel/og` renders accountability-framed cards matching DESIGN.md. Covers per-vote and per-rep-per-issue variants.
3. **Real-time ETL** — GitHub Actions every 15 min during session hours (or Vercel Cron), with dedup logic and correction-flow handling.
4. **Email alert system** — Subscription UI, Resend integration, daily/weekly digest, per-rep / per-issue scoping, unsubscribe + double-opt-in compliance, rep-migration on electoral changes.
5. **Journalist kit** — `/embed/vote/:id` iframe endpoint, Cite-this widget (APA/MLA/Chicago/BibTeX), methodology pages for every accountability metric (district-lean mismatch, donor correlation, pattern analysis), correction log.
6. **Historical backfill** — House + Senate roll calls back to 1999. Batched ETL separate from daily incremental. Handle pre-2010 schema variations.

## Risks to surface in /plan-eng-review

1. **SSR migration is a platform change.** Vite SPA → SSR/SSG is non-trivial. Lock the framework early; a wrong bet here cascades.
2. **Email deliverability** takes months to build. Start Resend/DKIM setup early, even before the UI is ready.
3. **SEO permalink stability** is load-bearing. If URL structure changes post-launch, you lose accumulated ranking. Design URLs to be forever-stable from day 1.
4. **Historical backfill + real-time ETL must not collide.** Dedup keys, idempotency, and ordering guarantees are critical.
5. **Methodology pages are editorial work.** Allocate writer time, not just engineer time.
