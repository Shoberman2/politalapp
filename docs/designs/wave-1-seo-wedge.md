## Goal

Ship per-vote SEO pages so BallotWatch ranks #1 for "did [rep] vote [issue]" queries. This is the wedge for the go-to-place ambition. Every Wave-2+ proposal (OG cards, email alerts, journalist embeds) depends on this foundation.

## Locked architectural decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | **Next.js App Router** on Vercel (not Astro, not vite-plugin-ssr, not Vite+prerender) | Boring-by-default, native Vercel ISR + @vercel/og + RSC, future-proofs Wave 2 share cards and middleware |
| 2 | **URL shape:** `/vote/{congress}/{chamber}/{roll}-{slug}` | Numeric prefix = forever-stable; slug = SEO keyword. Rep pages: `/rep/{bioguide}`. Rep-issue: `/rep/{bioguide}/issue/{policy-slug}`. Rep-vote: `/rep/{bioguide}/vote/{slug}` |
| 3 | **Rendering:** ISR with `revalidate: 3600` + `revalidateTag('vote:{id}')` on ETL update | Long-tail content, most pages rarely visited; ISR gives popular-page speed + long-tail cost = ~0 |
| 4 | **Schema deltas:** columns on `votes` + `bills` (no separate SEO table) | DRY; single RPC round-trip; slugs stay with the vote row |
| 5 | **Data fetching:** single Postgres RPC `get_vote_page_data(slug)` called from Server Component | One DB round-trip per ISR render; logic lives in SQL, reusable by /api/v1/* |
| 6 | **Migration shape:** clean-cut single PR (no Vite + Next coexistence) | Two routers = two systems; migration compresses to days with CC. Refactor first, ship features second |
| 7 | **Historical backfill:** separate `etl/backfillHistorical.ts` with `--congress=N` | Clean separation from daily ETL; UPSERT by `(roll_call_id, politician_id)` |
| 8 | **generateStaticParams:** last 90 days of votes only (~200-400 pages) | Rest render on-demand via ISR; fast builds |
| 9 | **Cache invalidation:** `app/api/revalidate/route.ts` with `ETL_REVALIDATE_SECRET` | ETL POSTs to Next after each run; post-deploy warming script for top-100 hot pages |
| 10 | **Connection pool:** Supavisor transaction-mode pooler (port 6543) for all RSC reads | Prevents serverless connection storms when a journalist tweets an old vote |
| 11 | **Slug policy:** freeze-on-publish + fallback chain + 301 redirects | Bill titles drift; slugs do not. See `Slug generation rules` below |
| 12 | **Policy area:** canonicalized via `policy_area_canonicalization` table | Congress.gov free-text changes ("Health" → "Healthcare") won't break rep-issue URLs |
| 13 | **ETL concurrency:** `pg_try_advisory_lock()` + `etl_leases` table | Real lock, not a boolean flag; crashed jobs expire after 1hr |
| 14 | **Stripe webhook:** stays as Vercel Function under `/api/webhooks/*` (Node runtime, raw body) | Next App Router body parsing breaks signature verification. Keep webhooks out of `app/api/` |
| 15 | **SSR-hostile components:** `'use client'` directive at component level | DistrictMap (react-simple-maps, d3-geo), Stripe checkout, `@vercel/analytics/react` hydrate client-side |

## Schema migration (Wave-1 deltas)

```sql
-- 1. Drop the colliding constraint, promote roll_call_id + politician_id
ALTER TABLE votes DROP CONSTRAINT IF EXISTS votes_politician_id_bill_id_voted_at_key;
ALTER TABLE votes ADD CONSTRAINT votes_roll_call_politician_unique
  UNIQUE (roll_call_id, politician_id);

-- 2. SEO metadata columns on votes
ALTER TABLE votes ADD COLUMN IF NOT EXISTS slug TEXT;
ALTER TABLE votes ADD COLUMN IF NOT EXISTS meta_description TEXT;
ALTER TABLE votes ADD COLUMN IF NOT EXISTS og_image_key TEXT;
ALTER TABLE votes ADD COLUMN IF NOT EXISTS slug_locked_at TIMESTAMPTZ;
CREATE UNIQUE INDEX IF NOT EXISTS idx_votes_slug ON votes(slug) WHERE slug IS NOT NULL;

-- 3. SEO metadata on bills
ALTER TABLE bills ADD COLUMN IF NOT EXISTS canonical_summary TEXT;
ALTER TABLE bills ADD COLUMN IF NOT EXISTS seo_title TEXT;
ALTER TABLE bills ADD COLUMN IF NOT EXISTS canonical_policy_area TEXT;

-- 4. Policy area canonicalization
CREATE TABLE IF NOT EXISTS policy_area_canonicalization (
  raw_value TEXT PRIMARY KEY,
  canonical_value TEXT NOT NULL,
  slug TEXT NOT NULL,
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 5. Slug redirects (for manual slug changes)
CREATE TABLE IF NOT EXISTS slug_redirects (
  old_slug TEXT PRIMARY KEY,
  new_slug TEXT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 6. ETL lease table
CREATE TABLE IF NOT EXISTS etl_leases (
  lease_key TEXT PRIMARY KEY,
  holder TEXT NOT NULL,
  acquired_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  expires_at TIMESTAMPTZ NOT NULL,
  metadata JSONB DEFAULT '{}'::jsonb
);

-- 7. The page-load RPC
CREATE OR REPLACE FUNCTION get_vote_page_data(p_slug TEXT)
RETURNS JSONB
LANGUAGE plpgsql STABLE AS $$
DECLARE result JSONB;
BEGIN
  SELECT jsonb_build_object(
    'vote', to_jsonb(v),
    'bill', to_jsonb(b),
    'politician', to_jsonb(p),
    'roll_call_stats', (SELECT to_jsonb(rcs) FROM roll_call_stats rcs WHERE rcs.roll_call_id = v.roll_call_id),
    'voting_pattern', (SELECT to_jsonb(vp) FROM voting_patterns vp WHERE vp.politician_id = v.politician_id AND vp.bill_id = v.bill_id),
    'donations', (SELECT jsonb_agg(to_jsonb(d)) FROM donations d WHERE d.politician_id = v.politician_id LIMIT 10)
  )
  INTO result
  FROM votes v
  LEFT JOIN bills b ON v.bill_id = b.id
  JOIN politicians p ON v.politician_id = p.id
  WHERE v.slug = p_slug;
  RETURN result;
END; $$;
```

## Slug generation rules

```
ETL slug chain (first that produces a non-empty slug wins):
  1. If vote.question exists and is specific → slugify(question)[:60]
  2. Else if bills.title exists            → slugify(bills.title)[:60]
  3. Else if motion_type exists            → "procedural-motion-" + slugify(motion_type)
  4. Fallback                              → "vote-" + roll_call_id

Freeze rule:
  If votes.slug_locked_at IS NOT NULL, never overwrite votes.slug.
  ETL sets slug_locked_at = NOW() on first write.
  If a slug change is needed later, manual operator action:
    INSERT INTO slug_redirects (old_slug, new_slug) ...
    UPDATE votes SET slug = <new>, meta_description = <new> WHERE id = <id>;
```

## Failure modes

| Codepath | Failure mode | Test? | Error handling? | User sees? |
|----------|-------------|-------|-----------------|------------|
| `app/(public)/vote/[...]/page.tsx` | invalid slug | YES | `notFound()` → 404 | 404 page |
| `app/(public)/vote/[...]/page.tsx` | DB down | YES | Error boundary → 500 page | "Try again soon" |
| `get_vote_page_data()` | bill_id null (procedural) | YES | LEFT JOIN returns null bill | Page renders with "Procedural vote" label |
| `etl/backfillHistorical.ts` | Congress.gov 429 | YES | Exponential backoff | — |
| `etl/backfillHistorical.ts` | process crash mid-run | YES | Lease expires in 1hr; resume with `--from-roll=N` | — |
| `/api/revalidate` | Invalid secret | YES | 401 response | ETL logs failure; retry |
| `/api/revalidate` | Unknown tag | YES | No-op, 200 response | — |
| `@vercel/og` render | Template data missing | YES | Fallback minimal card | Social share shows generic card |
| Supavisor pool exhausted | All RSC reads time out | YES (load test) | 500 with retry-after header | "Service busy" |
| Migration breaks existing route | User hits broken route | **CRITICAL** regression test | — | — (mustn't happen) |

**No critical gaps remaining** — every Wave-1 failure mode has a test AND error handling AND a user-visible fallback.

## Implementation phases (single PR, not sub-PRs — but ordered work)

**Phase 0 — schema + lock primitives** (blocking, 2-4 hrs)
- Migration: unique constraint fix, SEO columns, canonicalization + redirects tables, etl_leases, `get_vote_page_data` RPC
- Advisory lock helper in `etl/load.ts`
- Tests: migration idempotence, lock acquisition/release

**Phase 1 — slug generation + backfill prep** (4-6 hrs)
- `lib/slugify.ts` with freeze-on-publish rules
- `etl/backfillSlugs.ts` one-shot script to populate slugs for existing votes
- Test: deterministic, unicode-safe, truncation, fallback chain

**Phase 2 — Next.js scaffold** (6-8 hrs)
- Init Next App Router in the repo (keep `src/` during transition for reference)
- `app/layout.tsx`, route groups, middleware for auth
- `'use client'` audit on every existing component; tag each
- Port navigation + shared layout
- Regression test harness (Playwright): every existing route responds

**Phase 3 — Vote page implementation** (6-8 hrs)
- `app/(public)/vote/[congress]/[chamber]/[slug]/page.tsx`
- Server Component calls `get_vote_page_data`; renders with AI pattern + donor context
- `generateStaticParams` → last 90 days
- `generateMetadata` → canonical title, meta description, OG
- Error + notFound boundaries
- `/api/revalidate` route handler with HMAC-style secret check

**Phase 4 — Rep pages + issue pages** (4-6 hrs)
- `app/(public)/rep/[bioguide]/page.tsx`
- `app/(public)/rep/[bioguide]/issue/[policy]/page.tsx` (uses canonical_policy_area)
- `app/(public)/rep/[bioguide]/vote/[slug]/page.tsx`

**Phase 5 — Historical backfill execution** (in CI, multi-hour wall time)
- `etl/backfillHistorical.ts` — takes `--congress=N` flag
- Run manually against Congresses 106→119 (1999→current)
- Each run acquires advisory lock; blocks real-time ETL until complete

**Phase 6 — ETL upgrade + sitemap** (4-6 hrs)
- Update `etl/load.ts` to POST `/api/revalidate` after successful writes
- Generate sitemap.xml dynamically at `/sitemap.xml` route (Next convention)
- Post-deploy warming script for top-100 vote pages

**Phase 7 — Supavisor migration + connection hardening** (2 hrs)
- Update Supabase client init in `app/lib/supabase.ts` to use pooler URL
- Add pg statement_timeout default
- Load test vote page at 100 rps

**Total estimate:** human: 28-42 hrs / CC+gstack: 4-6 hrs active, +several hours of wall time for historical backfill runs.

## Worktree parallelization

Sequential — most phases touch `app/` or `etl/` which overlap heavily. Phase 5 (historical backfill) can run in parallel with Phase 6 (frontend feature work) once Phase 4 merges, but the coordination cost doesn't justify worktrees.

**Recommended execution:** single branch, phases in order, land as one PR.

**Hero metric:** rep photo + name + their vote position + one accountability signal sentence. The bill title is semantic `<h1>` but visually secondary to the accountability strip — it orients, it does not dominate. Voters are asking "did my rep represent me?", not "what was the bill?".

### Interaction state table

| Section | LOADING | HAPPY | PARTIAL | EMPTY | ERROR |
|---------|---------|-------|---------|-------|-------|
| Accountability hero | Skeleton: photo + line placeholders | Full render | Pattern not computed: render without signal sentence | N/A (rep+vote always present) | "We couldn't load this vote." |
| Bill summary | 3-line skeleton | Drop-cap lead paragraph | bill_id null (procedural): show motion_type, skip summary | "This was a procedural motion. No bill summary applies." | Silent fallback to senate.gov source link |
| AI marginalia | Subtle skeleton inside marginalia frame | Full block rendered | <5 prior votes in policy area: block renders with "Not enough voting history yet..." copy | Section renders with honest copy — "BallotWatch analysis: Not enough voting history yet to detect a pattern on food security. Check back as Rubio's record grows." | Section hidden; methodology link still visible |
| Donor context | Tabular skeleton | Industry + $ + sentence | No FEC data (freshman): "Sen. X took office in 2024. First FEC reporting due [date]" | "No campaign finance data available for this representative yet." | Section hidden |
| Roll-call strip | Grey cells placeholder | Colored cells | Voice vote: strip hidden, replaced with "Voice vote — no individual record" | Same as partial | Silent — strip hidden |
| Cite widget | Renders instantly (no data dep) | Full widget | Same | Same | Copy button disabled if clipboard API fails |
| 404 (invalid slug) | — | — | — | — | Editorial 404: "This vote isn't one we have a record of." + search |

Empty-state copy is warm and direct. Never "No data found" SaaS-speak.

- `<h1>` Bill title
- `<h2>` Rep name (hero strip)
- `<h2>` "Plain-English summary"

- Secondary #6B6861 → 5.4:1 ✓

## Rollback plan

- Schema migration is additive (nullable columns, new tables). Rollback: drop new columns (pre-reqs: no new writes outstanding). Keep promoted `(roll_call_id, politician_id)` unique constraint — that's a bug fix, don't revert.
- Next.js migration is all-or-nothing in a single PR. Rollback = `git revert` the PR. Existing Vite SPA continues to run from commit `78a8d4c`.
- Historical backfill is append-only. Rollback = delete the rows inserted for a given Congress: `DELETE FROM votes WHERE roll_call_id LIKE 'house-106-%'` (etc).

## Open risks (to monitor post-launch)

1. **Supavisor pool sizing.** Vercel Serverless scales fan-out; Supabase Pro plan pool limit is 200. Monitor; upgrade plan before public launch if needed.
2. **OG image cost.** Not in Wave 1 but schema provision is here. Wave 2 should include OG rendering load-test at social-crawler fan-out (Twitter, Slack, Facebook hit OG endpoints aggressively).
3. **Stripe webhook parity.** Regression test covers request/response shape; spot-check one real event in staging before cutover.
4. **react-simple-maps SSR.** Client-wrapped, but test that DistrictMap still hydrates cleanly on first load.
